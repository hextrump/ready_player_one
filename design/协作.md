# 训练机 ↔ GitHub ↔ 脚本机 — 协作约定

## 角色

| 机器 | 角色 | 主要职责 |
|---|---|---|
| **训练机** (本机) | 训练开发 | 训练管线、合成数据、模型导出 |
| **脚本机** (其他机器) | 战斗开发 | bot 主循环、感知调用、状态机 |

两台机器**共用同一个 GitHub 仓的 `main` 分支**,代码 100% 同步,**没有独立分支**。

## 模型同步: Git LFS

模型权重 (`*.pt` / `*.onnx` / `*.engine`) 走 Git LFS。
`.gitattributes` 自动接管,无需 `git lfs track` 手动声明。

### 训练机 → 推模型

```bash
# 训练完生成新模型
ls models/  # 例如: monster_v20.pt, super_brain_v14.pt

git add models/*.pt
git commit -m "feat(model): monster_v20 + super_brain_v14"
git push origin main
```

### 脚本机 → 拉模型

```bash
git pull
git lfs pull   # 关键: 拉 LFS 对象, 否则模型文件是空指针
```

**`git lfs pull` 必须手动跑** — `git pull` 默认不会拉 LFS 文件内容(只更新指针)。

## 不入仓的内容

`.gitignore` 屏蔽:

| 路径 | 说明 |
|---|---|
| `data/` | 训练数据 (13GB) |
| `cache/` | 运行时缓存 (atlas / mapledata_extracted / world.db 等) |
| `runs/` | 训练输出 |
| `*.log` | 训练日志 |
| `train_multimap.py` 等训练脚本 | 训练机本地迭代,不入仓 |
| `design/_local/` | 设计草稿 |

Syncthing 负责 `data/` + `cache/` + 训练脚本在训练机上的版本管理(如有需要)。

## 实战工作流

### 场景 1: 训练机导出新模型

```bash
# 在训练机上
python train_multimap.py   # 输出 models/monster_v20.pt
git add models/monster_v20.pt
git commit -m "feat(model): monster_v20 (mAP 0.85)"
git push origin main       # 脚本机自动能 git lfs pull 拿到
```

### 场景 2: 脚本机更新战斗逻辑

```bash
# 在脚本机上
# 改 src/brain/xxx.py
git add src/
git commit -m "fix(brain): 巡逻卡住脱困"
git push origin main       # 训练机 git pull 拿到代码
```

### 场景 3: 训练机改进感知模块

感知/状态机改动属于**主仓代码**,不是训练代码,直接 push:

```bash
# 改 src/perception/xxx.py
git add src/perception/
git commit -m "feat(perception): 怪物身份门控"
git push origin main
```

## 新机器接入清单

1. `git clone https://github.com/hextrump/ready_player_one.git`
2. 安装 Git LFS: `git lfs install`
3. `git lfs pull` 拉模型
4. 配 `config.yaml`(gitignored,从其他机器拷贝或模板生成)
5. 装 Python 依赖: `pip install -r requirements.txt`
