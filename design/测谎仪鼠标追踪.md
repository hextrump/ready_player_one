# 测谎仪（Lie Detector）鼠标追踪 — 设计文档

## 背景

ready_player_one bot 在战斗挂机时会遇到冒险岛的**测谎仪**（LIE DETECTOR）反挂机小游戏：

1. **倒计时阶段**（~7s）：弹窗底部三个石框，白色发光图形（五角星/怪物/卡通剪影）静止在其中一个框，顶部提示"N 秒后测谎仪微型游戏开始"。
2. **追踪阶段**：界面变成黄褐色沙土浮雕（布满星形凹槽），白色星形目标带编号，鼠标变成**绿色准星**（跟随系统光标）。目标在凹槽间移动，且**逐渐变透明**（提示文字："请用鼠标跟随逐渐变透明的图形"）。
3. 结束时弹窗关闭。玩家必须让鼠标光标持续落在目标上，否则可能掉线/被标记。

现状：bot 对测谎仪**无任何处理**。`EventType.CAPTCHA_DETECTED` 只是占位事件；`GameController` 只有键盘注入，**没有鼠标控制**；检测到测谎仪时 bot 只会继续打怪（可能反而加剧掉线风险）。

目标：战斗时检测测谎仪出现 → **暂停战斗** → 用**鼠标自动追踪白色图形** → 弹窗关闭后恢复战斗。

## 既有资产（本地 `lie-detector/` 项目）

本地 `C:\Users\heyas\Documents\code\lie-detector\`（独立项目，已跑通）已有一套**检测 + 跟踪系统**。bot 集成时直接 `import` / 薄包装，**不复制代码**：

| 组件 | 文件 | 说明 |
|---|---|---|
| 检测（OpenCV, CPU） | `scripts/auto_bbox.py` | `detect_lie_detector_window` + `detect_white_target`（多阈值 180/200/220/240，抗 fading，方形过滤） |
| 检测（OpenCV, CPU） | `scripts/white_silhouette_detector.py` | `detect_white_silhouette`（形状无关，返回 mask+centroid）+ `track_white_silhouette`（模板匹配跨帧跟踪） |
| 检测（多帧投票） | `scripts/multiframe_bbox.py` | 1 秒内取 10 帧投票找稳定白块（离线初始定位用） |
| 跟踪（SAM2.1/SAMURAI, GPU） | `samurai_repo/scripts/demo.py` + `samurai_repo/scripts/main_inference*.py` | bbox txt → 逐帧 propagate 生成 mask+box |
| **粘合层（推荐入口）** | `samurai_track.py`（项目根） | `detect_initial_bbox` + SAM2 `build_sam2_video_predictor` + propagate 循环 + 输出 mask/bbox/centroid/带覆盖层 mp4。一站式调用 |
| 一键管线 | `scripts/run_samurai_pipeline.py` | step1 多帧投票 → step2 SAMURAI → mp4。已修过 GBK/绝对路径 |

用户要求：**不用 YOLO**；用 OpenCV 初始定位图形，再用 SAMURAI 跟踪；先在 GPU 上调试；集成进 bot。

> **集成策略**：bot 不复制这些函数。`src/perception/samurai_tracker.py` 改为薄包装：把 `lie-detector/` 加进 `sys.path`（或用 `subprocess` 调 `samurai_track.py`），复用 `detect_initial_bbox` + SAMURAI propagate 循环，逐帧返回中心坐标给 `MouseTracker`。

## 验证发现（2026-08-24 本地实测）

用真实片段 `2PlrcMKRAFM_clip1_0-13s.mp4`（1280x720@60fps，含倒计时+追踪全流程）验证：

1. **管线端到端可跑通**（exit 0，输出 17MB mp4）。需要修 3 处才能跑：
   - venv 缺依赖：装 `tqdm`、`portalocker`（iopath 依赖）、`supervision`、`einops`。
   - 管线打印 `✓` 在 GBK 控制台 `UnicodeEncodeError` → 运行需 `PYTHONIOENCODING=utf-8`。
   - demo.py 在 `samurai_repo/scripts` 的 cwd 下运行，**相对视频路径解析不到** → 视频/模型路径必须用绝对路径（用户示例 `C:/Users/.../BV1QxcKzXEHT.mp4` 正是绝对路径）。
2. **OpenCV 检测工作正常**：多帧投票锁定星形 bbox `(582,259,31,23)`。但**沙色窗口检测 FAILED**（实际窗口是深灰/沙土浮雕，非纯沙色）→ 回退全帧白块检测才找到。窗口检测对实际游戏外观需重新校准。
3. **SAMURAI 在移动阶段跟丢**：t=3（倒计时）SAMURAI 覆盖层在星形上（输入/输出 diff 中心 ≈ 星形中心）；t=9/11（追踪阶段）覆盖层消失（mask 为空）。原因：**初始 bbox 太紧**（31x23，远小于星形整体）+ 倒计时→移动的**窗口布局剧变**，SAM2 内存跟踪失配。
4. demo.py 的覆盖层颜色是**蓝色** `color=[(255,0,0)]`（BGR），不是文档说的绿框。

## 方案

架构：新增**测谎仪感知模块（CPU）** + **鼠标控制** + **战斗大脑接线**；跟踪器做成可插拔后端（`samurai` GPU / `opencv` CPU），自动或配置选择。

### 1. 新模块 `src/perception/lie_detector.py`（薄包装 + 状态机，**不复制**）

bot 不复制检测函数。直接从本地 `lie-detector/` import（项目根加进 `sys.path`，或 pip install -e / submodule）：

- `from lie_detector.scripts.auto_bbox import detect_lie_detector_window, detect_white_target`（多阈值抗 fading）。
- `from lie_detector.scripts.white_silhouette_detector import detect_white_silhouette, track_white_silhouette`（模板匹配兜底）。
- `from lie_detector.scripts.multiframe_bbox import detect_multiframe`（初始定位兜底）。

封装为 `LieDetector` 状态类，视觉线程逐帧调用 `update(frame) -> LieDetectResult`：
- 输出 `active` / `target_center` / `target_bbox` / `phase` / **`confidence`** / **`brightness`**（§9 自适应速度用）。
- **去抖**：连续 K 帧命中才激活，连续 M 帧丢失才解除（防战斗特效误触发）。
- **bbox 膨胀**：把亮核 bbox 放大到完整星形（解决 SAMURAI 初始框过紧的跟丢问题）。
- 窗口检测失败回退全帧（与 `auto_bbox` 一致）。
- **依赖路径**：`config.yaml` 配 `lie_detector.detector_repo_path: C:/Users/heyas/Documents/code/lie-detector`，bot 启动时 `sys.path.insert(0, repo_path)`。

### 2. `src/brain/game_controller.py` — 加鼠标控制

- `client_to_screen(cx, cy)`：`win32gui.ClientToScreen(hwnd, (0,0))` + 客户区偏移。
- `move_mouse(cx, cy)`：`win32api.SetCursorPos(屏幕坐标)`（游戏白手套/绿准星跟随系统光标）。
- `move_mouse_smooth(target, max_step, hz)`：多步缓动逼近（拟人，非瞬移）。

### 3. 新模块 `src/brain/mouse_tracker.py` — 鼠标跟随线程

独立线程：测谎仪激活期间以 ~30Hz 读最新目标中心（视觉线程写入的共享状态），缓动移动光标；解除/超时停止。

### 4. `src/brain/combat_brain.py` — 集成

- **视觉线程** `_perception_loop`：`find_targets` 之后跑 `lie_detector.update(frame)`，结果写入 `self.world`（`WorldState`/`WorldSnapshot` 新增 `lie_active` / `lie_target`）。
- **决策循环** `run()`：`snap.lie_active` 为真 → 决策返回 `("lie_detector", None)`，暂停打怪/接近/巡逻；同时 `capture.bring_to_front()`（测谎需窗口可见，游戏才读得到光标位置）。
- **动作执行** `_action_worker`：处理 `"lie_detector"` 动作 → 启动/复用 `MouseTracker`，直到 `lie_active` 解除或超时。
- **坐标映射**：视觉帧是 letterbox 后 1366x768 → un-letterbox 回客户区 1600x900（scale/pad 来自 `letterbox_array`）→ `ClientToScreen` 得屏幕坐标 → `SetCursorPos`。需给 `WindowCapture` 暴露最近一次 letterbox 参数。

### 5. `src/state/events.py` — 事件化

新增 `LIE_DETECTOR_ACTIVE` / `LIE_DETECTOR_CLEARED` 事件类型，激活/结束时写入 GlobalBus（复用 `CAPTCHA_DETECTED` 持久化模式）。

### 6. `config.yaml` — 可配置

`lie_detector:` 小节：`enabled`、激活/解除去抖帧数、鼠标最大步长/Hz、超时、`backend`。

### 7. SAMURAI 后端（GPU，薄包装）

`src/perception/samurai_tracker.py` **不重写** SAM2 包装。直接复用 `lie-detector/samurai_track.py` 已跑通的逻辑（OpenCV 初始定位 → SAM2 propagate → 逐帧中心）：

- **方案 A（推荐，进程内 import）**：
  - `config.yaml` 配置 `lie_detector.detector_repo_path`，bot 启动时 `sys.path.insert(0, repo_path)`。
  - `from samurai_track import detect_initial_bbox` 复用 OpenCV 初始定位（已含沙色窗口 + 全帧回退）。
  - `from sam2.build_sam import build_sam2_video_predictor`（`sys.path` 指向 `samurai_repo/sam2`，**非 repo 根**，避免 shadowing）。
  - 初始化：读取首帧 → `detect_initial_bbox` → `predictor.init_state(video_frames_iter, ...)` → `add_new_points_or_box(state, box=bbox, frame_idx=0, obj_id=0)`。
  - 跟踪：`predictor.propagate_in_video(state)` 生成器，每帧 yield `(frame_idx, object_ids, masks)`，取 `obj_id=0` 的 mask → bbox → 中心 → 喂给 `MouseTracker`。
- **方案 B（独立子进程）**：若 bot 进程不想碰 SAM2/GPU 依赖，直接 `subprocess` 跑 `samurai_track.py`，通过 stdout JSON / 共享文件回传中心。**代价**：每帧 IPC 延迟高，运行时不如方案 A。**仅在 GPU 隔离/沙箱场景用**。
- **抗漂移 re-init**：`LieDetector` 每帧仍跑 `detect_white_target`；若连续 N 帧 SAMURAI mask 为空且 OpenCV 重检出 bbox → 用新 bbox 调 `predictor.add_new_points_or_box` 重新初始化（不是重建 predictor，state 复用）。
- **GPU 现实**：SAM2.1 必须有 GPU（`torch.cuda.is_available()`）；无 GPU 笔记本回退 `backend="opencv"`（星形大部分时候高亮可跟，渐隐后期精度下降——已知限制）。
- **依赖与路径**：
  - venv 需 `tqdm / portalocker / supervision / einops`（iopath 间接依赖）。
  - `sys.path` 顺序：`samurai_repo/sam2`（sam2 包）→ `samurai_repo/scripts`（samurai 包装）→ `lie-detector/` 根（`samurai_track.py`）。
  - 所有视频/模型路径用**绝对路径**（`demo.py` 的 cwd 在 `samurai_repo/scripts`，相对路径解析不到——验证发现 #1）。
  - 控制台运行需 `PYTHONIOENCODING=utf-8`（GBK 控制台 `UnicodeEncodeError`——验证发现 #1）。
  - 模型权重：`samurai_repo/sam2/checkpoints/sam2.1_hiera_{base_plus,large}.pt`。

### 8. 拟人化鼠标（运行时）

原 §2 `move_mouse_smooth` 是线性缓动，机械感强 → 容易被反作弊识别。新增独立模块把轨迹/速度/抖动/人味停顿封装，**只影响运行时**（SAMURAI/OpenCV 后端不变）：

- 新模块 `src/brain/human_mouse.py`：
  - `HumanMouseController.move_to(current_xy, target_xy, duration_ms, cfg)`：从当前位置到目标生成多步 `SetCursorPos` 调用序列。
  - **轨迹**：2 段贝塞尔，控制点 = `(start, mid+δ, target)`，`δ` 在 `±bezier_jitter` px 内随机（默认 2px），整段轨迹沿贝塞尔等弧长采样 N 个中间点。
  - **速度曲线**：sigmoid `v(t) = 1 / (1 + e^{-k(t-0.5)})`，归一化后乘 `duration_ms`，得每步时间戳。**不是匀速**（启动慢、中段快、收尾减速）。
  - **微抖**：每步位置叠加 `±jitter_amplitude` px 高频抖动（默认 0.5px，频率 = 步率）。模拟手抖，不破坏落点。
  - **随机停顿**：以 `pause_prob`（默认 5%）在轨迹 30%~70% 区间插入 30~80ms 停顿，停顿期间不动光标。
- `src/brain/mouse_tracker.py`：把 `move_mouse_smooth` 调用替换为 `human_mouse.move_to(...)`，每次目标更新触发一次完整轨迹生成（而不是单步）。
- `config.yaml` 新增 `lie_detector.human_mouse`：
  - `enabled: true`
  - `bezier_jitter: 2.0`  `jitter_amplitude: 0.5`
  - `pause_prob: 0.05`  `pause_min_ms: 30`  `pause_max_ms: 80`
  - `duration_min_ms: 60`  `duration_max_ms: 180`  （轨迹总时长按距离插值）
- **降级**：`human_mouse.enabled=false` 回退到原 `move_mouse_smooth`（调试/对比用）。

### 9. 自适应速度（基于目标透明度）

测谎追踪阶段目标**渐隐**（§背景）。固定 Hz/速度在渐隐后期跟不上 → 鼠标停在原地 → 判定失败。运行时按检测置信度动态调采样率和单步最大位移：

- `src/perception/lie_detector.py`：`LieDetector.update` 输出新增字段：
  - `confidence` ∈ [0, 1] = `matched_thresholds / total_thresholds`（多阈值检测天然有这信号——`detect_white_target` 用 180/200/220/240，命中几个就几分之几）。
  - `brightness` ∈ [0, 255]：当前目标 ROI 平均亮度（来自 OpenCV mask 内像素均值）。
- `src/brain/mouse_tracker.py`：
  - **采样率**：根据 `confidence` 在 `hz_low`(默认 20Hz, 高 confidence) ↔ `hz_high`(默认 60Hz, 低 confidence) 间线性插值。
  - **单步最大位移**（即轨迹速度上限）：同插值，`step_low` � `step_high` px/帧。`step_high` 必须够大以追上渐隐期目标移动速度，但不超过原 `max_step`。
  - 切换用低通滤波，避免 Hz/速度在阈值附近抖动（`alpha=0.3` EMA）。
- `config.yaml` 新增 `lie_detector.adaptive_speed`：
  - `enabled: true`
  - `hz_low: 20`  `hz_high: 60`
  - `step_low: 8`  `step_high: 24`  （px/帧，屏幕坐标）
  - `conf_threshold: 0.5`  （< 此值进高频区）
- **依赖**：§8 拟人化轨迹生成也用这套 Hz/速度上限，确保两层不冲突（轨迹总时长由 `duration_ms` 决定，单帧内部仍走贝塞尔；自适应只决定"多久重新生成一次轨迹"）。
