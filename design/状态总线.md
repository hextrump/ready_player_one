# 状态总线设计 (World State Bus)

> 本文是 `设计思想.md` 在这个 bot 上的落地。核心那句话:
> **上下文不能碰瓷状态机, 不能碰瓷对象身份。**
> 感知每帧吐出的是 evidence/observation, 不是系统状态。系统状态必须经过
> 分类 → 归属 → 类型化 → 校验 → 状态转换, 才配叫状态。

---

## 一、为什么原来"卡卡的"

2026-08-19 21:08 的真实日志 (战士 / 射手村 / 打猪猪), 三段病症:

```
[_attack] 目标 dx=175 超出所有攻击范围, fallback 近战 -> Monster
[ATTACK] 目标消失/移出范围,提前结束 (共 0 下)
[ATTACK] Monster × 0 击 @ (866,431)          ← 每 100ms 重复一次, 刷了几十行
[STATE] attacking → approaching              ← 100ms 后
[STATE] approaching → attacking              ← 又 100ms 后 ... 30 秒转换 300+ 次
[PLAYER] 名牌连续漏检, 玩家位置开始向画面中心衰减
[STATE] 玩家=(751,473) ... 玩家=(996,379) ... 玩家=(696,432)   ← 待机中, 人根本没动
```

根因都不是"参数没调好", 而是**同一个事实有多个真源**:

| 现象 | 根因 |
|---|---|
| `× 0 击` 空转 | 决策用 `engage + buffer(80)` 判"在射程内", 执行用 `engage` 判"够得着"。**两个判定函数**, 结论能相反 → 决策发 attack、执行打 0 下、返回、决策再发 attack。 |
| 战士射程静默为 0 | `is_in_attack_range(key=...)` 默认 `"bullet"`, 而战士 bullet 射程 = 0。所有忘了传 key 的调用 (滞回锁定、巡逻的"进范围就停") 对战士**恒为 False**。走路永远不会因为"打得到了"而停下。 |
| 状态 100ms 横跳 | 决策 10Hz、感知 7Hz, 没有最小驻留, 也没有目标承诺 → 边界上的怪每帧都能翻案。 |
| 决策/执行看到不同世界 | `_decide` 读一次锁、`_walk_toward` 又读一次、`_attack` 再读一次 —— 三次读到的是**三个时刻**的世界。 |
| 玩家位置乱跳 300px | 名牌参考图命中就**无条件 commit**, 没有连续性门控 → 一帧锁到隔壁那个人。 |
| 参考图路径 0 命中 | 尺度常数 `REF_SCALE_BASE=0.85` 是按**旧那张**名牌图标定的; 重新采集名牌后常数静默失效 (实测真实尺度 1.00, 用 0.85 峰值 0.562 < 阈值 0.60)。于是身份判定退化成"选屏幕上最靠下的名牌" —— **谁站得低谁就是我**。 |
| 换角色认错人 | 名牌是全局文件 `models/nametag/nametag.png`, 靠 `swap_player` 复制的**副作用**传递。切到没有名牌的模板时, 文件还是上一个角色的。 |

一句话: **身份和射程这两个"事实", 被写在了好几个地方, 而且互相不知道。**

## 二、总线分层 (把图投影成树)

现实是图: 玩家↔怪↔平台↔梯子↔相机 谁都能发生关系。全塞进决策层就是 O(n²) 的 if。
所以按"谁拥有这个事实"投影成一棵树, 每个事实**只有一个所有者**:

```
WorldState              ← 感知线程单写
├── PlayerState         ← 玩家身份与位置 (唯一所有者)
│     confidence: CONFIRMED / STALE / LOST
│     source:     ref / body / badge / v13
│     收敛协议:   commit / propose / reject / decay / far_streak 翻案
├── MonsterTracker      ← 怪的身份与生命周期
│     Monster.id 跨帧稳定, seen_frames / miss_frames
├── TerrainTracker      ← 平台/梯子的身份 (世界坐标 + 相机位姿)
└── motion / fps / seq  ← 帧元数据

        ↓ snapshot()  (锁内一次, 值拷贝)

WorldSnapshot (frozen)  ← 决策/执行/移动层的唯一输入
        ↓
CombatBrain._decide(snap) → ("attack"|"approach"|"patrol"|"none", target)
        ↓
ActionExecutor (独立线程, 按目标 id 去重, 可 cancel)
        ↓
BrainLedger → GlobalBus (SQLite)   ← 账本: 状态转换/身份丢失/击杀/卡死
```

### 2.1 快照 (WorldSnapshot) —— 一次决策 = 一个世界

```python
snap = brain.refresh_snapshot()      # 锁内冻结: 玩家 + 怪(值拷贝) + 地形 + motion + seq
act, tgt = brain._decide(snap)       # 同一 seq 内所有判断自洽
```

- **不可变** (`frozen=True`), 怪是值拷贝 —— 感知线程接着跑不会改写已发出的决策。
- 移动层的 `player_pos()` / `any_target_in_range()` 也走快照 (120ms 内复用同一份),
  不再各自加锁散读。
- 带 `seq` 和 `age_ms()`: 谁都能判断"我手上这份世界有多旧"。

### 2.2 身份 (PlayerState) —— 位置是实体的属性, 不是每帧的选美结果

定位器只产 `NametagObservation(ok, x, y, source, match)`, **采不采信由实体决定**:

| 情况 | 处理 |
|---|---|
| `LOST` | 无条件采信 (没有身份要保护, 拒绝只会让 bot 一直瞎着) |
| 位移 ≤ 60px | 直接 commit (正常走动) |
| 60 ~ 260px | 两帧落在同一处才 commit (跳跃/下跳是真的, 一帧的瞬移不是) |
| > 260px | 默认拒绝 (那是别人的名牌); 但连续 4 帧落在同一处 → **翻案接受** (换图/传送/上一帧本来就锁错了) |
| 无观察 | miss+1 → 8 帧降 `STALE` → 30 帧降 `LOST` 并向画面中心衰减 |

`confidence` 会传到决策层: 不是 `CONFIRMED` 时, 移动层关掉脱困跳 (位置冻结会假触发狂跳),
怪的自排除框也关掉 (拿"画面中心猜测"去挖洞会把中心的真怪一起挖掉)。

### 2.3 名牌 = 身份凭证, 属于模板

```
data/player/player0_warrior/
  ├── warrior.json      ← 战斗参数
  └── nametag.png       ← 身份凭证 (运行时由 PlayerProfile.identity 解析)
```

- `PlayerProfile.identity.nametag_path` 从**模板目录**解析, 绝不回落全局文件。
- 模板没有名牌 → 启动 WARNING + HUD 显示 `(NO NAMETAG)`, `swap_player` 直接拒绝切换 (除非 `--force`)。
- 参考图尺度**自动标定** (启动时全帧多尺度扫一次, ~0.4s), 不再是代码里的常数。
  重新采集名牌后自动重新标定, 不会静默失效。
- `tools/capture_nametag.py --player <模板>` 直接存进模板目录。

实测效果 (射手村 28 帧真实截图): 参考图路径命中 **0/28 → 26/28**。

### 2.4 射程判定唯一入口

```python
brain.is_in_attack_range(target, px, py, hold=False)   # engage: 能不能开打
brain.is_in_attack_range(target, px, py, hold=True)    # hold:   要不要继续打
```

- `engage = profile.engage_range_x = max(近战射程, 远程射程)` —— 战士 120, 火枪手 350。
  **没有 key 参数了**, 调用方不需要知道自己是什么职业。
- `hold = engage + attack_range_buffer` —— buffer 只做滞回 (打的过程中怪走到边缘别松手),
  **不参与选目标**。这是 `× 0 击` 空转的直接修法。
- 不变量 (有测试盯着): `is_in_attack_range(t) ⟹ is_in_attack_range(t, hold=True)`,
  即"决策放行的目标, 执行一定够得着"。

### 2.5 状态机: 合法性 + 最小驻留 + 账本

```python
transition_to(new_state, reason="", force=False)
```

三道闸:
1. **STANDBY 全局 override** —— 按 F 停手 / 无药看门狗, 任何状态直接进 (原来会报"非法转换"再绕一圈)。
2. **最小驻留** —— 只约束"降级" (打→接近→巡逻→扫描), 升级 (→ATTACKING) 永不受限。
   `ATTACKING 0.40s / APPROACHING 0.35s / PATROLLING 0.30s`。被挡下的次数记在 `blocked_count`。
3. **合法性表** `ALLOWED_TRANSITIONS` —— 不在表里就是状态图有洞, 记警告走 SCANNING 兜底。

外加**目标承诺**: 已锁定的怪只要还在 hold 射程内就继续打, 按 `id` 找回 (不用像素距离猜)。

### 2.6 账本 (BrainLedger)

低频事实异步写 SQLite (`data/state.db`), 队列满就丢 —— **账本可以缺页, 决策不能卡**:

- `STATE_CHANGED`: from / to / reason / dwell / seq
- 身份丢失与重新捕获 (含 miss_frames / rejects, 用来判断"是不是旁边有人")
- 击杀 (真击杀: burst 中目标消失且确实打过。`kill_count` 不再把 0 击空转算成击杀)
- 卡死升级 (哪个状态超时了, 升级成了什么)

查询:
```python
from src.state.global_bus import GlobalBus
from src.state.events import EventType
GlobalBus().query_events(EventType.STATE_CHANGED, limit=100)
```

## 三、修改后的不变量 (测试在 `tests/test_combat_state.py` 盯着)

1. 决策放行 attack 的目标, 执行层起手守卫必过 (无 0 击空转)。
2. 快照发出后, 感知线程的后续帧不会改写它。
3. 已确认的身份不会被单帧远处观察推翻; 但连续一致的证据能翻案。
4. 状态降级受最小驻留约束, 升级不受;`STANDBY` 任何时候可进。
5. 同状态重复 `transition_to` 不刷新 `entered_at` (否则超时 watchdog 永远不触发)。

逐帧跑完整管线并把结果画出来人工看 (`data/_verify_bus/f*.png`):

|---|---|

| 攻击不变量 | 所有 `attack` 决策, 执行层起手守卫均通过 (无 0 击空转) |

**这轮验证抓到的新问题** (已修): 战士模板 `filter_conf=0.12` 太松, 22 个低分框里 9/10 是杂物 ——
树冠 / 蘑菇装饰 / 传送门光柱 / **鼠标指针** / **自己的宠物花蘑菇仔**。传送门光柱距玩家 281px,

这个参数原本放这么松, 正是为了补偿"玩家定位不准 → 永远不进射程"; 定位修好后补偿不再需要。

## 五、第二轮实测修的两个问题 (2026-08-19)

### 5.1 名牌锁到经验条 → HUD 上一堆绿框乱飞

参考名牌图是"深色横条 + 亮字",而 **HP/MP/经验条也是深色横条** ——
`TM_CCOEFF_NORMED` 在这种低细节图案上会在 UI 上打出更高的峰。实测某帧全帧前 6 个峰:

```
峰0 score=0.664 y比例=0.96   ← 经验条
峰1 score=0.610 y比例=0.96   ← 经验条
峰3 score=0.564 y比例=0.89   ← 聊天栏
真名牌反而落选
```

更致命的是**尺度标定也被 UI 带偏**:标成 `scale=0.65`(真值 1.00),一旦标错,
之后每一帧都往经验条上锁 → 玩家十字被拉到屏幕底部,绿框到处乱飞。

修法:给参考图路径加位置先验上界 `REF_PLAYER_Y_MAX = 0.78`(与 HSV 路径的
`Y_MAX_BOX=600/768` 同口径),**搜索和标定都只在这条竖直带内做**。
修后:70 帧里 ref 命中 56 / badge 12 / miss 2,命中 y 比例全部落在 0.46~0.64,UI 带(0.89~0.96)一个都没有。

### 5.2 走路时地形错位 → 巡逻扫图和地形对不上

地形模型每 `TERRAIN_EVERY=3` 帧才跑一次,而相机位姿 `world_offset` **原来只在跑地形的那一帧更新**。
走路时镜头每帧滚动约 35px,中间两帧完全没人补偿。用受控平移实验量化(平台中心误差,已排除边缘裁剪假象):

| | 地形帧 | 中间帧 1 | 中间帧 2 | 总均值 | 最坏 |
|---|---|---|---|---|---|
| 修前 | ~1px | 35px | 71px | **35.8px** | **75.5px** |
| 修后 | ~1px | 0.6px | 1.0px | **0.9px** | **4.0px** |

对比容差:`WALK_EDGE_MARGIN=25` / `ROPE_GRAB_DX=30` / `SURFACE_TOL_Y=30` ——
75px 是容差的 2~3 倍,所以走路时"到边缘该转身""这里有梯子可以爬""脚下是不是平台"全判错。

修法:`_estimate_camera_shift()` 每帧用**相位相关**在 320x180 缩略图上测镜头位移
(裁掉顶部小地图和底部 UI,它们在屏幕上不动会把位移拉向 0),再 `apply_camera_shift()`
并入位姿。实测位移精度 −34.8 vs 真值 −35,耗时 **2ms/帧**,静止 40 帧零漂移。
地形模型仍然每 3 帧跑一次做绝对纠正,相位相关只负责中间帧的相对跟随。

## 六、巡逻: 目标驱动 (看地形 → 去最远的地方)

### 6.1 为什么"定时换向"必然像脚本

相机跟着玩家走,**屏幕坐标里玩家几乎不动**。所以按时间翻向的巡逻:

- 不知道自己在地图的哪里
- 不知道已经走了多远、走过哪里
- 只能靠计时器翻烧饼

调随机化只能让节拍不那么规整,治不了根 —— 试过两版:
固定 3s 翻向 (跨度 375px) → 6~15s 随机承诺 (跨度 1374px),看着还是左摇右晃。

### 6.2 现在的做法

**目标点存世界坐标**。上一节为地形做的相机位姿 (`world_offset`) 正好可以用:
`world = screen + offset`,镜头怎么滚,目标都钉在原处。

```
每次巡逻:
  1. 卡住检测 (位置/画面都不动 → 脱困 + 放弃目标)
  2. 附近有怪 → 目标 = 那只怪的世界坐标
  3. 目标到了 / 超时 / 没有 → 从地形重新选一个
  4. 朝目标连续走 3 秒 (不是 0.5 秒一抽一抽)
  5. 路上遇到平台边缘 → 爬梯 / 边缘上跳 (_at_edge)
```

**选点规则**(这就是"看地形"):

| | |
|---|---|
| 候选 | 每块平台的左右端点 + 每根梯子的上下端 |
| 排除 | 隐含地面节点 (宽 2000000px,端点是假的) |
| 得分 | 距离;同方向 ×1.35 (防到了就掉头);刚去过 ×0.45 (防在一处反复刷) |
| 门槛 | 至少比当前位置远 250px,否则不值得当"远处目标" |
| 兜底 | 地形选不出来 → 朝当前方向推 900px 继续探索 |

关键点:候选是**当前可见地形**的端点,只有半屏远。但走到之后新地形进入视野,
新的端点更远 —— 于是自然形成"一路走到地图尽头"的连续推进,到头了没有更远的点,
最远的候选就变成反方向,自动折返。这正是人扫图的样子,不需要全地图先验。

### 6.3 实测 (世界模型模拟: 地图全宽 3000px,可见范围 ±683px,60 秒无怪)

| 版本 | 60 秒跨度 | 行为 |
|---|---|---|
| 固定 3s 翻向 | 375px | 原地小幅来回 |
| 6~15s 随机承诺 | 1374px | 幅度大了,仍是翻烧饼 |
| **目标驱动** | **2465px** | 走到右端 1298 → 折返走到左端 −1301 → 再折返 |

真实帧上验证:用射手村实拍地形选点,选出"平台左端,905px 外"。

### 6.4 还没做

小地图黄点实测 **98% 命中** (129/132 帧),它能给**整张图**的绝对坐标与范围,
而当前方案只能看见半屏。有了它可以做:整图访问计数(哪片区域刷空了)、
跨层扫图规划、可靠换图检测。当前方案在单层长图上已经够用,多层复杂图会露怯。

## 七、移动: MovePlan (怎么过去, 收敛成一个类型)

### 7.1 病象与根因

人卡在下层平台来回蹭, 上层平台的怪不去打。

根因是"我够不够得到那只怪"被**在两个地方各用 dx/dy 魔法数现推一遍**:
`is_reachable`(决策层)判一次, `approach`(执行层)又判一次, 阈值还不一样。
而两处共用的兜底启发式要求 `dx <= jump_to_upper_dx(150)` —— 怪必须在头顶正上方。

实测 (射手村 132 帧): **60 例"怪明显在上方却判不可及", 无一例外都是**
`dx 在 262~519px` + 怪不在任何检测平台上。而按表面落差分桶:

| 落差 (脚底口径) | 例数 |
|---|---|
| 同层 (≤30px) | 348 |
| **一跳可上 (30~140px)** | **458** |
| 要爬梯 (140~300px) | 6 |

也就是说绝大多数"怪在上面"本来就跳得上去 —— **缺的动作是"先走到它下面, 再跳"**。

然后 `is_reachable=False` → 决策走 patrol → 而 patrol 会把 360px 内的怪设成目标,
**"到达"只比 x** → 走到怪正下方就算到了 → 换目标 → 怪还在 → 又设回来。
这就是"卡在下面平台"的完整闭环。

### 7.2 设计: 收敛成一个确定的数据结构

按 `设计思想.md`: evidence 不能直接当 state 用, 要经过分类 → 类型化 → 收敛。

```python
class MoveKind(Enum):
    WALK / JUMP_UP / DROP / CLIMB / UNREACHABLE

@dataclass(frozen=True)
class MovePlan:
    kind: MoveKind
    takeoff_x: int | None   # 起跳/抓梯点
    surface_dy: float       # 表面落差 (正=目标在上方)
    reason: str             # 为什么是这个结论 (账本化, 日志直接可读)
```

**唯一生产者** `plan_move(target, px, py, platforms, ropes)`;两个消费者:

| 消费者 | 用法 |
|---|---|
| `is_reachable` (决策层) | `plan.kind is not UNREACHABLE` |
| `approach` (执行层) | 按 `plan.kind` 执行 |

于是"决策放行的, 执行一定做得了"成为一条**可测试的不变量** —— 与射程的
`engage ⟹ hold` 完全同构。

判定规则:

| 条件 | 结论 | 起跳点 |
|---|---|---|
| 落差 ≤ 30px | WALK | — |
| 上方 ≤ 140px (单跳) | **JUMP_UP** | 目标平台正下方 (两端各内缩 40px);平台没检出来就取怪的 x |
| 上方 > 140px + 有跨层梯子 | CLIMB | 梯子 x |
| 上方 140~280px 无梯子 | **JUMP_UP (试跳)** | 怪的正下方 |
| 上方 > 280px | UNREACHABLE | — |
| 下方 ≥ 50px | DROP | 走出边缘 (见第五节) |

执行 JUMP_UP 时**先走到起跳点再跳**(原来完全缺这一步);站定后原地跳即可 ——
冒险岛平台单向, 从下方能穿上去。

**起跳点取怪的正下方, 不依赖地形检测**:怪站在那儿, 就说明那儿有个能站的地方。
检测到平台时只拿它做微调(别贴边跳),而不是当前提 —— 实测那 60 例上方怪,
一个平台都没检出来。同理"没检测到梯子"是**否定证据**, 不足以推出"够不着":
落差在 [单跳, 单跳×2] 之间时先去试跳, 跳不上由 `JUMP_FAIL_LIMIT` 次失败学到。

另外 patrol 只追**够得着**的怪 (`plan.kind is not UNREACHABLE`), 这是"来回蹭"的直接修法。

### 7.3 接近的时间预算也不能是常数

`STATE_TIMEOUT_SEC[APPROACHING] = 4.0` 是另一个"写死的常数其实描述的是一个关系"——
"接近该给多久" = 路程 ÷ 速度。实测需走 >250px 才到起跳点的目标有 178 个,
中位 451px(3.6s)、最大 1085px(8.7s)——**4 秒看门狗会在半路把它判成"走不到"**,
于是远处高台上的怪永远打不到。

改成 `MovePlan.travel_px` 带出路程,决策层按 `2.5 + 路程/125 × 1.8`(封顶 15s)给预算,
换目标时重新计时。100px → 3.9s,451px → 9.0s,1085px → 15s。
